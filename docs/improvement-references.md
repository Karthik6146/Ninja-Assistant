## Actual local integrations

- **Ollama:** existing HTTP adapter, actual installed-model health, streaming visible answers and bounded calls. Uses existing httpx/filelock. Loopback only for the local provider; no inference subscription, but local memory/compute and deliberate model downloads are required. No model weights/license are redistributed.
- **ClipX:** inspected the supplied local repository's manifests, session and upload implementation. Root npm workspaces contain Next 14 web on port 3000 and a separate worker. `/api/upload` creates a video/project/job without a caller idempotency key. Therefore Ninja opens the existing app rather than duplicating jobs or inventing an API contract. No dependency/source copied; ClipX owns its credentials, media processing, dependencies and license obligations. Default status honestly reflects whether its page identifies itself as ClipX.
- **YouTube:** existing official-API adapter and encrypted Windows credential storage retained; no new account, API quota, paid media generation or publication was used in this update. Local preparation is separate from explicitly approved external actions.
- **MCP / browser:** metadata reports Not configured and empty capabilities. A future connection requires a real server/runtime, reviewed permissions, validated schemas, timeout/cancellation behavior and explicit external-data consent. No simulated tools are advertised.

Ninja keeps existing validated tool schemas/permissions/timeouts in `tools.py`, provider I/O in `adapters.py`, durable workflow execution in `workspace.py`, and protected HTTP routes in `workspace_routes.py`. The selected scope adds no runtime dependency or framework fork.

Ollama preparation reports use the official [structured-output JSON schema field](https://docs.ollama.com/capabilities/structured-outputs) on the existing chat endpoint; ordinary chat remains free text. Application-side citation validation is still required.
