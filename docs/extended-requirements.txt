C. Test generation inspired by Qodo Cover
The upstream README states Qodo Cover is unmaintained. Treat it as an optional development integration, disabled by default, with a pinned revision and verified compatibility.

Implement a maintained core workflow using pytest/pytest-cov for Python and the project’s chosen frontend test tools:
1. Run relevant existing tests and establish a baseline.
2. Inspect uncovered branches and actual behaviour.
3. Generate focused candidate tests.
4. Execute them in an isolated workspace.
5. Reject flaky tests, fabricated expectations, and tests that merely mirror implementation.
6. Report behavioural value and coverage changes.
7. Limit retries, runtime, and model spending.

Never weaken assertions, delete failing tests, or modify production behaviour solely to increase coverage. Avoid enforcing 100% coverage everywhere. Prioritize permissions, paths, approvals, job recovery, caption timing, upload reconciliation, and publication states.

If Qodo Cover is used, keep it optional and document its AGPL-3.0 license and maintenance limitations without assuming compatibility or offering blanket licensing conclusions.
